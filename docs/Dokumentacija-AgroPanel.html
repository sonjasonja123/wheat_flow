1. Korisnički zahtev

1.1. Verbalni opis teme

AgroPanel je veb aplikacija namenjena malim i srednjim poljoprivrednim gazdinstvima koja se bave proizvodnjom pšenice. Sistem predstavlja digitalni dnevnik gazdinstva: čuva podatke o parcelama, prati proizvodnju od setve do žetve, evidentira troškove, planira radne aktivnosti, obaveštava zaposlene i prikazuje analitičke izveštaje.

Ciljni korisnici su vlasnici gazdinstava, menadžeri proizvodnje, agronomi, radnici i administratori. Interfejs je prilagođen i korisnicima bez naprednog tehničkog znanja, sa jasnim formularima, padajućim listama, porukama o uspehu ili grešci i responzivnom navigacijom.

1.3. Nefunkcionalni zahtevi

  • Bezbednost: JWT autentifikacija, bcrypt heširanje lozinki, kontrola pristupa na API-ju i frontendu, Helmet zaglavlja, ograničenje pokušaja prijave i izdvajanje tajni u .env.
  • Performanse: optimizovan React build i REST odgovori; k6 scenario proverava postepeno opterećenje do 500 virtuelnih korisnika.
  • Upotrebljivost: responzivan dizajn, jasne oznake polja, izbori iz lista i konkretne poruke validacije.
  • Portabilnost: Docker slike i konfiguracija preko promenljivih okruženja omogućavaju pokretanje na različitim cloud platformama.
  • Pouzdanost: health endpoint proverava dostupnost baze; priložena je skripta za rezervnu kopiju i postupak dnevnog zakazivanja.
  • Kompatibilnost: interfejs podržava aktuelne verzije Chrome, Firefox, Edge i Safari pregledača.

Dostupnost od 99%, HTTPS sertifikat i stvarno dnevno izvršavanje backupa zavise od produkcione cloud infrastrukture. Projekat obezbeđuje potrebne konfiguracione osnove, ali se ove vrednosti potvrđuju tek nakon postavljanja i monitoringa.

2. Opis sistema i slučajevi korišćenja

2.1. Glavni tok rada

  1. Korisnik se prijavljuje email adresom i lozinkom.
  2. Sistem proverava nalog, vraća JWT i prikazuje navigaciju prilagođenu ulozi.
  3. Ovlašćeni korisnik dodaje parcelu i bira njenu tačku na mapi.
  4. Za parcelu se otvara proizvodnja pšenice i upisuju agrotehnički podaci.
  5. Troškovi se povezuju sa parcelom i konkretnom proizvodnjom.
  6. Menadžer ili agronom planira aktivnost i dodeljuje je radniku.
  7. Radnik dobija obaveštenje, izvršava zadatak i označava ga završenim.
  8. Vlasnik pregleda prinos, prihod, troškove, profitabilnost i poređenje sezona.

2.2. SK1 — Kreiranje parcele

Akteri: administrator, menadžer ili vlasnik. Preduslov: korisnik je prijavljen. Postuslov: parcela je trajno sačuvana.

  1. Korisnik otvara modul Parcele.
  2. Unosi naziv, pozitivnu površinu, tip zemljišta, lokaciju i sezonu.
  3. Tačku bira na mapi ili upisuje validnu geografsku širinu i dužinu.
  4. Sistem validira podatke i šalje zahtev API-ju.
  5. Nakon uspeha prikazuje se poruka da je parcela sačuvana.

Alternativni tok: uz neispravnu površinu, sezonu ili koordinate, korisnik dobija preciznu poruku uz problematičan podatak; zahtev se ne čuva.

2.3. SK2 — Evidentiranje proizvodnje

Akteri: sve operativne uloge. Korisnik bira parcelu, popunjava podatke o pšenici i čuva proizvodnju. Sistem odbija nelogičan redosled datuma. Nakon uspešnog unosa prikazuje potvrdu i osvežava listu.

2.4. SK3 — Planiranje zadatka

Akteri: administrator, menadžer, agronom i vlasnik. Kreira se aktivnost sa datumom, parcelom, beleškom i zaduženim korisnikom. Sistem pravi lično obaveštenje. Radnik vidi samo svoje zadatke i može da menja njihov status i belešku.

2.5. SK4 — Analiza profitabilnosti

Akteri: administrator, menadžer, agronom i vlasnik. Korisnik bira godinu i parcelu. Sistem sabira prinos, prihod (prinos × cena), troškove i računa dobit ili gubitak. Rezultat se prikazuje karticama i grafikonima, a može se izvesti.

3. Arhitektura i model podataka

3.1. Arhitektura

Sistem koristi troslojnu klijent–server arhitekturu. React aplikacija predstavlja prezentacioni sloj. Express REST API sadrži rute, autentifikaciju, validaciju i poslovna pravila. Sequelize ORM povezuje poslovni sloj sa MySQL bazom.

React klijent → Axios/REST/JSON → Express rute i middleware → kontroleri → Sequelize → MySQL

Spoljne integracije su Google Maps za izbor koordinata i Open-Meteo za trenutne vremenske podatke. Chart.js radi lokalno nad podacima dobijenim iz AgroPanel API-ja.

6. API i bezbednost

6.1. REST API

API je organizovan po resursima: /api/users, /api/fields, /api/productions, /api/expenses, /api/activities, /api/contracts, /api/notifications i /api/reports. Swagger interfejs je dostupan na /api-docs.

6.2. Bezbednosne mere

  • Lozinke se nikada ne vraćaju kroz listu korisnika i čuvaju se kao bcrypt hash.
  • JWT sadrži identifikator korisnika i ulogu, traje jedan dan i šalje se u Authorization zaglavlju.
  • Backend proverava ulogu pre osetljivih akcija; sakrivanje menija nije jedina zaštita.
  • Helmet postavlja bezbednosna zaglavlja, JSON telo je ograničeno, a prijava ima rate limit.
  • JWT tajna, podaci baze i Google Maps ključ nalaze se u lokalnim .env datotekama ignorisanim u Gitu.
  • HTTPS se uključuje na reverse proxy ili cloud platformi u produkciji.

7. Docker, CI/CD, backup i cloud

7.1. Docker

Docker Compose pokreće MySQL, backend i frontend. Baza koristi trajni volumen. Backend dobija parametre baze kroz environment promenljive, pa nije vezan za localhost niti jednu cloud platformu.

docker compose up --build

7.2. CI/CD

GitHub Actions se aktivira za granu main i pull request. Pipeline instalira zavisnosti sa npm ci, pokreće backend testove, gradi produkcioni frontend i proverava izgradnju obe Docker slike. Namerno ne objavljuje slike na tuđi Docker Hub nalog; objava se može dodati kada vlasnik repozitorijuma definiše svoje secrets vrednosti.

7.3. Backup, dostupnost i cloud

Skripta scripts/backup-db.ps1 koristi mysqldump i pravi vremenski označenu rezervnu kopiju. U produkciji se zakazuje najmanje jednom dnevno i kopija se čuva van servera. Endpoint /api/health proverava i API i vezu sa bazom, pa ga cloud monitoring može koristiti za upozorenja i restart.

Aplikacija se može postaviti na AWS, Azure, Google Cloud, Render ili sličnu platformu koja podržava kontejnere. Za produkciju treba podesiti upravljanu MySQL bazu, jaku JWT tajnu, HTTPS domen, politiku CORS-a, backup raspored i monitoring dostupnosti.

8. Testiranje i vizuelizacija

8.1. Automatizovani testovi

Backend koristi Jest i Supertest za proveru osnovnog API-ja i zaštićenih ruta. Frontend koristi React Testing Library, a produkcioni build ujedno proverava kompajliranje svih komponenti. CI izvršava iste provere na svakom push-u.

Komande:

cd backend npm test -- --runInBand cd ../frontend npm run build

Za proveru cilja od 500 istovremenih korisnika priložen je k6 scenario u scripts/load-test.js. Konačne performanse zavise od hardvera i cloud konfiguracije i moraju se izmeriti u okruženju sličnom produkcionom.

8.2. Vizuelizacija

Google mapa pretvara klik korisnika u validnu geografsku širinu i dužinu. Izveštaji koriste stubičaste i kružne grafikone: seme i prinos po proizvodnji, raspodelu troškova po tipu i poređenje prihoda, troškova i dobiti između sezona.

9. Pokretanje projekta

  1. Instalirati Node.js 18+ i MySQL 8.
  2. Kreirati bazu agriculture_db.
  3. Kopirati backend/.env.example u backend/.env i popuniti podatke.
  4. Kopirati frontend/.env.example u frontend/.env i uneti Google Maps ključ.
  5. U backend direktorijumu izvršiti npm install i npm start.
  6. Jednom pokrenuti seed-test-data.sql ako su potrebni testni podaci.
  7. U frontend direktorijumu izvršiti npm install i npm start.
  8. Otvoriti http://localhost:3000. Testna lozinka je Test123!, a email nalozi su navedeni u SQL skripti.

10. Zaključak

AgroPanel realizuje centralizovano upravljanje proizvodnjom pšenice i povezuje operativne, finansijske i kadrovske podatke. U odnosu na početni projekat, uvedeni su izbor koordinata na mapi, detaljna validacija, pšenica kao domen, padajuće liste sa unosom novih vrednosti, profitabilnost, poređenje sezona, izvoz, vremenski podaci, aktivnosti, ugovori, preciznije dozvole, sigurnosna poboljšanja i pouzdaniji DevOps postupak.

Predložena naredna unapređenja su skladištenje dokumenata uz ugovore, naprednija prognoza bolesti pšenice, 2FA i automatsko slanje email ili push obaveštenja.
